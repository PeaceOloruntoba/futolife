FUTO Life

Walk the campus together. You will start at the central entrance, the one location we treat as verified.

1. Product architecture

One persistent world, with everything else as overlays on it. The 3D scene never unmounts; panels are sheets (mobile) or side drawers (desktop). Switching tabs must not drop the socket or reload assets.

LayerContents
World (always on)Scene, avatar, camera, other players, proximity detection
HUDLocation chip, camera toggle, map, people, joystick, context action button
SheetsMap, People, Building, Profile, Emotes, Settings
InteriorsSeparate scene chunk loaded on entry, same HUD with reduced controls

Routes (for the engineer): / world · /?poi=id deep link to a place · /b/:id interior · /u/:id profile. Overlays use query state so the back button closes them.

2. First-time journey (3 steps, under 30 seconds)

Welcome → controls tutorial (joystick, camera, interact) learned by doing, not reading → spawn at the central entrance with one guided prompt toward the nearest place. Sign-in is deferred: guests can walk; social features ask for sign-in at first use. Show a download-size and quality choice (Low/Med/High) before the first asset load, defaulting by device.

3. Exploration interface

ElementDecision
MovementLeft-thumb floating joystick, tap-to-move with a ground marker, WASD on desktop. Run when pushed to the rim.
CameraToggle 1st/3rd. Third is default (spatial awareness plus seeing your avatar). Look by dragging the right half of the screen. Auto-switch to first person indoors in tight spaces.
DiscoveryPlaces reveal a soft label within about 40 m, a full prompt within about 8 m. Map shows only visited and verified places by default.
InteractionOne contextual action button (right thumb). It changes label: Enter, Talk, Wave, Sit. Never more than one primary action at a time.

4. Approaching and entering buildings

Distance states: far (label fades in) → near (door glows, prompt card) → at door (action button becomes Enter) → transition (0.35 s fade, no loading bar if the interior is preloaded on "near") → interior with a sheet showing real information and who is inside. Leaving returns you to the same door.

5. Multiplayer and social

Presence first, chat second. Nearby players are shown as avatars with name plates. Tap a person: Wave, Follow, Invite to walk together, Message. Quick emotes via a radial menu. Proximity text bubbles, not a permanent chat log. Privacy: visibility modes (Everyone, Friends, Ghost), mute and report on every profile, no precise real-world location sharing.

Assumptions and open items

No FUTO building names, layouts, or coordinates were invented. Apart from the central entrance (verified by you), all places in the prototype are labelled Placeholder. The prototype is a top-down UX blockout, not the 3D scene; camera toggle only changes the framing to demonstrate the interaction.

Needed before build: verified POI list with coordinates and photos, permission to use campus imagery, moderation policy for a student community, a decision on identity (school email verification vs guest), server and concurrency targets, and an asset budget for low-end Android devices.

Engineer notes

Suggested split: a scene module (Three.js or Babylon, render loop, camera rig), an input module (joystick, keys, tap-to-move), a presence module (WebSocket, interpolated remote players at 10 Hz), and a UI module in the framework of choice. POI data should be one JSON file: {id, name, verified, lat, lng, doorPos, interiorId, info} so unverified items can be shown differently by the verified flag.

Visual direction

Dusk-lit, cinematic, and grounded: dark UI that gets out of the way of a realistic scene, with warm gold for action and a teal for social presence. Glass surfaces with a thin line, no heavy shadows, no dashboard cards.

Type and shape

System UI stack for now. Suggest a licensed display face for titles later. Labels 11 px caps, body 14 px, titles 17–30 px. Radii 14 px (controls), 18 px (sheets), full circle for joystick and action. Touch targets at least 44 px.

Motion

Sheets 300 ms ease. Door transitions 350 ms fade. Prompt cards fade 150 ms. Respect prefers-reduced-motion: replace slides with fades.

Components

Location chip · camera toggle · icon button · joystick · context action · proximity prompt · bottom sheet · player row · name plate · verified/placeholder tag. Each is a single reusable component driven by tokens above.

Accessibility

Joystick size and left/right handedness configurable, optional auto-walk to a selected place, captions for any future voice chat, contrast of at least 4.5:1 on all HUD text.
